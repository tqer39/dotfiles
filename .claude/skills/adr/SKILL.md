# アーキテクチャ決定記録の作成

依頼文で指定された題材について、対象リポジトリの `docs/adr/` に ADR を作成します。
以下のパスは対象リポジトリのルート基準です。
`docs/rules/documentation.md` があれば読み、文書の言語と命名に適用します。
なければ対象リポジトリの規約に従います。

## 手順

1. `docs/adr/` の既存ファイルを調べ、次の連番を決めます（例：0003）。
2. 題材や決定内容が不明な場合はユーザーに確認します。決定が未採用なら採用済みと記載しません。
3. `docs/adr/NNNN-<kebab-case-title>.md` を作成し、以下の形式で背景・選択肢・判断理由を記載します。
4. 対象リポジトリの手順に従って Markdown を検証します。dotfiles では `mise run lint` を使います。

## ADR の形式

```markdown
# ADR-NNNN: <タイトル>

## ステータス

[提案中・採用済みなど、実際の状態]

## コンテキスト

[背景、問題、要件を記述]

### 要件

- [要件1]
- [要件2]

## 検討した選択肢

### 選択肢1：<名前>

- [説明]

### 選択肢2：<名前>

- [説明]

## 決定

**<選択肢>** を採用する。

## 理由

| 観点 | 選択肢1 | 選択肢2 |
| ---- | ------- | ------- |
| ...  | ...     | ...     |

### 主な決定理由

1. [理由1]
2. [理由2]

## 結果

[実装の結果を記述]
```
