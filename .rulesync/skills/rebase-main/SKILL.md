# main へのリベース

依頼された作業ブランチを最新の `origin/main` にリベースします。
別のリモートやベースブランチを指定された場合は、その指定を優先します。

## 手順

1. 作業ディレクトリ、現在のブランチ、リモート、未コミット変更、進行中の Git 操作を確認します。
   main 上や detached HEAD、別のリベース・マージの途中なら、そのまま開始せずユーザーに確認します。
2. 未コミット変更・未追跡ファイルがある場合は、退避方法を確認してから進めます。
   自動で stash・コミット・破棄しません。
3. `git fetch origin main` で最新を取得します。失敗したら停止し、古い参照で続けません。
4. `git -c rebase.autoStash=false rebase origin/main` を実行します。
5. 競合が発生したら双方の変更意図を確認し、解消したファイルだけを `git add` して
   `git rebase --continue` で継続します。判断がつかない場合は競合箇所を示してユーザーに確認します。
6. 完了後に差分と対象リポジトリのテスト・lint を確認し、結果を報告します。

## 注意事項

- 競合解消のために、片側の変更を一括で捨てたりコミットを無条件にスキップしたりしません。
- 自分が開始したリベースは `git rebase --abort` で中止できます。
  ユーザーが先に開始していた Git 操作を勝手に中止しません。
- リベースの依頼だけでは push しません。push も依頼された場合は、ローカル検証を先に完了します。
  履歴の書き換えが必要なら対象ブランチとリモートの更新を確認し、無条件の強制 push は使いません。
